## Rollback and release gate

A trial release must set both --dart-define=LOCALSPOT_TRIAL_RELEASE=true and --dart-define=LOCALSPOT_BACKEND_URL=https://<approved-worker-host>. Startup rejects a missing Worker endpoint and rejects HTTP, emulator/LAN hostnames, and literal IP addresses, preventing a trial APK from silently falling back to Firebase Functions. The read-only preview keeps its separate LOCALSPOT_PREVIEW=true path.

Do not remove legacy Functions code or its trigger until the Worker workflow is validated. The current Flutter integration falls back to Firebase Functions when `LOCALSPOT_BACKEND_URL` is unset; that fallback is not a no-Blaze production rollback. If the trial Worker fails, disable affected features or roll back the app release until a Spark-compatible backend path is restored. A signed APK is not ready until it points only to the authorized internet Worker endpoint, uses the trial Firebase project, contains no emulator/LAN URLs or private keys, and passes physical Android workflow and security checks.
